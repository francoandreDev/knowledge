You are at Home and want to get to School. The map shows two ways. One has
**two rides** (Home to Central, Central to School) and takes **23 minutes**.

**Which route is "the shortest"?** Both answers are defensible. Fewest rides

## What are you really drawing when you draw a map?

**If you strip the map of colours, curves and street names, what is left?**
Only two kinds of thing: places, and connections between places. That is a
graph.

- **Nodes** (vertices) are the things: stations, people, services, commits.
- **Edges** are the connections between two nodes: a track, a friendship, a call.

```mermaid
flowchart LR
    Home ---|"6 min"| Central
    Central ---|"17 min"| School
    Home ---|"4 min"| Park
    Park ---|"5 min"| Mall
    Mall ---|"6 min"| School
    Mall ---|"3 min"| Library
```

That is the whole subway map: 6 nodes and 6 edges. The numbers on the edges are
minutes, invented for this unit. Everything else in graph theory is a property
added to this two-part structure.

Two yes/no questions describe almost any graph you will meet:

| Question about the edges              | If yes                                        | If no                                         |
| ------------------------------------- | --------------------------------------------- | --------------------------------------------- |
| Does an edge only work one way?       | **Directed**: a one-way street, "A follows B" | **Undirected**: a friendship, a two-way track |
| Does an edge carry a number (a cost)? | **Weighted**: minutes, kilometres, a fare     | **Unweighted**: every edge counts as one step |

The subway map is undirected (a track runs both ways) and weighted (minutes). A
list of which service calls which is directed, and weighted only if you care
about something like latency.

## So which route is the shortest?

**Why did the two answers disagree?** Because each one measures the path by a
different rule:

| What you count                | Route Home to School     | Result     |
| ----------------------------- | ------------------------ | ---------- |
| Edges used (rides)            | Home, Central, School    | 2 rides    |
| Sum of edge weights (minutes) | Home, Park, Mall, School | 15 minutes |

So "shortest path" is a family of questions, and each needs a different tool:

| If every edge counts as 1 step | If edges have non-negative weights |
| ------------------------------ | ---------------------------------- |
| **BFS** (breadth-first search) | **Dijkstra's algorithm**           |
| Finds the fewest edges         | Finds the lowest total weight      |

Using BFS when you care about minutes does not crash. It returns a route that
looks reasonable and is wrong for your question, which is the more dangerous
failure.

## One more thing worth knowing before L2

A program has to store this map somewhere. The two standard layouts differ in
how many numbers they hold. For the 6-station map above, a station-by-station
grid holds $$6 \times 6 = 36$$ cells, while a per-station list of neighbours
holds 18 entries (6 stations plus 12, because each of the 6 undirected tracks is
listed from both ends). The demo below lets you grow the network and watch the
gap open up. L2 explains why.

## Key terms

- **Graph** — a set of nodes and a set of edges between them.
- **Directed / undirected** — whether an edge has a direction.
- **Weighted** — whether an edge carries a number such as minutes or cost.
- **Path** — a sequence of edges leading from one node to another.
- **Cycle** — a path that leads back to where it started (L3 uses this).
- **BFS / Dijkstra** — the fewest-edges and lowest-total-weight search algorithms.
