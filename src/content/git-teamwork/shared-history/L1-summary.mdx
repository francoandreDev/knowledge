A developer rebases their own local commits to clean up the history
before pushing — a normal, everyday habit. They run
`git push --force` on a shared branch. A few minutes later, a
teammate discovers their own commit — pushed to that same branch just
before the force-push — is gone from the remote. No error, no
warning, no conflict. **The developer only touched their own
commits. So how did someone else's already-pushed work disappear?**

</Scenario>

## The shape of the problem

- A **force-push** doesn't merge or reconcile histories — it replaces
  whatever the remote branch currently points to with whatever the
  local branch currently points to, discarding any remote commits
  that aren't reachable from the new local tip.
- The danger isn't rebasing itself, and it isn't force-pushing itself
  — it's force-pushing **based on a stale view of the remote**. If
  the remote has moved since the last fetch (because a teammate
  pushed in the meantime), a force-push based on the old view silently
  throws away whatever moved.
- Git has a safer alternative built for exactly this: **`--force-with-lease`**,
  which refuses to push if the remote branch has moved since the
  last time it was fetched — turning a silent, destructive overwrite
  into a rejected push with a clear reason.

## Key terms

- **Shared history** — commit history on a branch that more than one
  person pushes to or bases work on, as opposed to a purely personal
  branch nobody else touches.
- **Force-push (`--force`)** — a push that overwrites the remote
  branch's history with the local branch's history, regardless of
  whether the remote has commits the local branch doesn't have.
- **Ancestor commit** — commit A is an ancestor of commit B if B's
  history, traced backward through parent commits, eventually reaches
  A. A normal (non-force) push only succeeds if the remote's current
  tip is an ancestor of the new tip being pushed.
- **`--force-with-lease`** — a safer form of force-push that fails if
  the remote branch has moved since the last fetch, instead of
  silently overwriting whatever is there.

## What this unit covers

L2 works through exactly what a force-push does to the remote
branch's ref, and why a normal push (without force) refuses to
overwrite commits it doesn't already know about. L3 builds a small
commit-history simulation to measure precisely which commits the
Scenario's naive force-push actually destroys, and shows how
`--force-with-lease` would have caught the problem before it happened.
