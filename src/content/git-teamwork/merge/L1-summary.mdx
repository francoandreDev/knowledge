Alex and Sam both branched off the same commit of `cart.js` this morning.
Alex added a guard clause; Sam changed a constant. Neither has seen the
other's work. **When Sam runs `git merge alex-branch`, does git need a
human to sort this out, or can it figure it out alone?**

</Scenario>

## The shape of the problem

- Two people editing the **same file** on different branches isn't
  automatically a conflict — most of the time, git resolves it without
  asking anyone anything.
- What actually decides "auto-merge" vs. "human, please look at this" is
  **which exact lines** each side touched, not which file.

## Key terms

- **Merge base (common ancestor)** — the last commit both branches share
  before they diverged. Git needs this to tell the difference between "Alex
  added this line" and "this line was always there."
- **Three-way merge** — comparing the merge base against _both_ branches
  (not just comparing the two branches directly against each other) is
  what lets git attribute each change to whoever made it.
- **Auto-merge** — when the two branches changed different lines, git
  combines both changes into the file automatically, no conflict.
- **Conflict** — when both branches changed the _same_ line to _different_
  content, git can't guess which one you want and stops to ask.
- **Conflict markers** — `<<<<<<<`, `=======`, `>>>>>>>` — how git shows
  you both versions, inline in the file, so you can pick or combine them.
- **Fast-forward merge** — a special case where one branch is simply
  "ahead" of the other with no divergence at all; git just moves the
  branch pointer forward, no merge commit, no chance of conflict.

## When Git asks for help

A conflict is not Git destroying work. It is Git refusing to guess. The
minimum human loop is:

1. Open each conflicted file.
2. Read the sections between `<<<<<<<`, `=======`, and `>>>>>>>`.
3. Decide the final content: choose one side, combine both, or write a
   better version.
4. Delete the conflict markers.
5. Run the relevant test, build, or manual check.
6. Stage the resolved file with `git add`, then finish the merge.

Deleting markers only fixes the file's shape. It does not prove the
combined logic is correct, so the test/check step is part of the merge,
not optional cleanup.

## What this unit covers

L2 works through _why_ three-way (not two-way) comparison is the trick
that makes auto-merge possible, and what fast-forward looks like by
contrast. L3 builds a real, simplified three-way merge algorithm in code
and runs it against Alex and Sam's actual file — once where they don't
overlap (auto-merges clean), and once where they both touch the exact
same line (produces a real conflict, markers and all).
