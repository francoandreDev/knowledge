## Which strategy is "one layout that stretches" and which is "pick a template"?

- **Responsive design**: one flexible layout that keeps reflowing as the width changes, using relative sizes (`%`, `fr`, `clamp()`) plus a few `@media` breakpoints where the structure changes. The browser does the adapting.
- **Adaptive design**: a small, fixed set of layouts, each built for a known device class. Something (a server, an app) picks the closest one; nothing flows in between.

| Question                           | Responsive                                   | Adaptive                                         |
| ---------------------------------- | -------------------------------------------- | ------------------------------------------------ |
| How many layouts exist?            | One flexible layout                          | Several fixed layouts (often 3 to 6)             |
| What decides the layout?           | The browser, continuously, from actual width | A device match, chosen once                      |
| New device width (e.g. a foldable) | Reflows automatically                        | Needs a new fixed layout or falls back awkwardly |
| Typical cost                       | Design once, more CSS complexity             | Design and maintain N layouts separately         |
| Common use                         | Most modern websites                         | Legacy sites, kiosks, print, email templates     |

The phone/laptop/4K bug reports at the top are what happens with **neither** strategy: one fixed layout, no breakpoints, no fluid sizing. Responsive design fixes it by reflowing continuously; adaptive design fixes it by swapping in a different pre-built layout.

## What are breakpoints and fluid sizing, and where do they fit?

- **Breakpoint**: a width where the _arrangement_ changes (three columns become two, a sidebar becomes a menu). Structure is discrete, so it jumps.
- **Fluid sizing**: a value written as a formula of the viewport width (`clamp()` is the modern tool), so it changes smoothly with no jump. Type size and spacing are the usual candidates.

```mermaid
xychart-beta
    title "Common breakpoint tiers (px)"
    x-axis ["Small phone", "Large phone", "Tablet", "Laptop", "Desktop", "4K"]
    y-axis "Viewport width (px)" 0 --> 4000
    bar [360, 480, 768, 1024, 1440, 3840]
```

These are common reference points, rounded from real device widths, not a law. Most sites use them as starting guesses, then move each breakpoint to where their own content strains (L2 covers how).

Most production sites today are responsive-first and reach for adaptive only for very different experiences (a print layout, a kiosk, an email client with poor CSS support). L2 and L3 build the mechanics and the judgment call.
