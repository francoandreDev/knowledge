You walk up to a librarian and say, "Do you have anything about animals?"
The librarian gestures at three floors of shelves. You try again: "I need a
book for an eight-year-old about how octopuses change colour." Within a
minute you are holding the right book.

Nothing about the library changed between the two asks. The librarian knew
the same things both times. **What did the second question carry that the
first one did not, and can you build that into any search box, not just a
person?**

The same thing happens online. Jordan's home Wi-Fi drops for a few seconds,
several times a day. The first search, "wifi keeps disconnecting," returns
over 40,000 results: old forum threads, contradictory advice, half of it
about other routers entirely. Twenty minutes later Jordan knows nothing new.
The second search adds the router's model number and the word "intermittent."
The second result is the manufacturer's own support page, describing this
exact fault and linking the fix.

## Why does a vague question get a vague answer?

**Was the first search broken?** No. A search engine, like the librarian,
returns everything that plausibly matches what you said. "Wifi keeps
disconnecting" matches every Wi-Fi complaint anyone has posted. The answer
existed; the question could not point at it.

An **anchor term** is a word or phrase specific enough that it can only
appear in sources about your actual situation: a model number, an exact error
message, a version, a precise symptom. In `[router model] intermittent
disconnect`, the square brackets mean "replace this with the model printed on
your own router". They are not typed literally.

| Vague words                    | Anchor terms that do the work                  |
| ------------------------------ | ---------------------------------------------- |
| "phone problem"                | Phone model plus the exact message on screen   |
| "school form"                  | School name, form name, and the year           |
| "stomach medicine side effect" | Medicine name, dose, and the symptom's wording |
| "wifi broken"                  | Router model plus "intermittent disconnect"    |

## What did the second search change?

|                          | Search 1                          | Search 2                                                 |
| ------------------------ | --------------------------------- | -------------------------------------------------------- |
| Query                    | "wifi keeps disconnecting"        | "[router model] intermittent disconnect"                 |
| Results                  | 40,000+, mostly unrelated         | A short list, mostly relevant                            |
| Time to a useful answer  | 20+ minutes, still unresolved     | Under 2 minutes                                          |
| What made the difference | Nothing specific to Jordan's case | Model number and exact symptom, both learned in search 1 |

Two more ideas complete the picture:

- **A bad first search is not wasted if it teaches you better terms.**
  Skimming it surfaced the model number and the word "firmware" in other
  people's posts. Those became search 2's anchors.
- **Some questions have one place the answer actually lives**: the maker's
  support page, the official documentation, the changelog. Once you suspect
  that, searching inside that source beats searching around it.

The skill this unit builds is treating the first search as scouting, not as a
one-shot bet, and noticing when to stop scouting and go to the source.
