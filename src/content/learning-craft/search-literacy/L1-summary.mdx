Jordan's home Wi-Fi drops for a few seconds, several times a day. First
search: "wifi keeps disconnecting." Over 40,000 results — years-old forum
threads, contradictory advice ("it's your router," "it's your ISP," "it's
your microwave"), half of it about different routers entirely. Twenty
minutes in, Jordan still doesn't know what's actually wrong. **Same
problem, same person, same amount of typing — what would it take to get a
useful answer in the next search instead of the next twenty minutes of
scrolling?**

Jordan tries again: "[router model] intermittent disconnect known issue."
The second result is the manufacturer's own support page — describing this
exact symptom as a known firmware bug, with a linked update that fixes it.
**The problem didn't get easier. The question got more specific.**

</Scenario>

- **A vague query returns a vague, contradictory result set — not because
  the answer doesn't exist, but because "wifi keeps disconnecting" matches
  every unrelated Wi-Fi problem anyone has ever posted about.** The search
  engine isn't failing; it's doing exactly what a vague query asks it to
  do: return everything remotely related.
- **Specific, exact terms narrow the search space dramatically.** A router
  model number, an exact error message, an exact symptom — each one rules
  out everything that doesn't match it. Ten years of unrelated forum posts
  can't match "[this exact model] intermittent disconnect," because most
  of them aren't about this model at all.
- **Some questions have one authoritative place the answer actually
  lives** — the manufacturer's own support page, the official
  documentation, the changelog, the spec — and once you suspect that's
  true, searching around the topic repeatedly is slower than going
  straight to that source and searching _within_ it.
- **A bad first search isn't wasted if it teaches you better terms for the
  second one.** Jordan's first search didn't answer the question, but
  skimming it surfaced the router's model number and "firmware" as a
  relevant word — both of which made the second search specific enough to
  work.
- The practical skill this unit builds: treating the first search as a
  **reconnaissance step that generates better terms**, not a one-shot bet
  — and recognizing when to stop broad-searching and go straight to a
  specific, authoritative source instead.

## What changed between the two searches

|                          | Search 1                      | Search 2                                                       |
| ------------------------ | ----------------------------- | -------------------------------------------------------------- |
| Query                    | "wifi keeps disconnecting"    | "[router model] intermittent disconnect known issue"           |
| Results                  | 40,000+, mostly unrelated     | A handful, mostly relevant                                     |
| Time to a useful answer  | 20+ minutes, still unresolved | Under 2 minutes                                                |
| What made the difference | —                             | Exact model number + exact symptom, both learned from search 1 |
