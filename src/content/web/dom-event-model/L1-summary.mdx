A todo app's delete button has a small trash icon inside it. Clicking
near the edge of the button deletes the item. Clicking directly on the
icon — which visually looks like part of the same button — does nothing
at all. **The user clicked the same button both times. Why did only one
click register?**

The click handler checks whether the exact element the user clicked has
the class `delete-btn`. When the click lands on the button's edge, the
element clicked _is_ the button, and the check passes. When the click
lands on the icon, the element clicked is the icon — a completely
different element, nested inside the button — and the check silently
fails, because the icon doesn't have the class `delete-btn` at all.

</Scenario>

- **A click doesn't happen "on a button" in some abstract sense — it
  happens on one specific element**, and if that element has children
  (like an icon inside a button), the exact element reported as clicked
  can be the child, not the outer element a person would call "the
  button."
- **The DOM event model calls this `event.target`: the innermost, most
  specific element the click actually landed on** — which is not
  necessarily the element that has a click handler attached, or the
  element a developer meant to check against.
- **Events bubble: after firing on the target, the same event fires again
  on each ancestor, all the way up to the document.** This is what lets
  code attached to a button's _ancestor_ — or even the whole page — react
  to a click that technically landed on a descendant like an icon.
- **Bubbling is also what makes event delegation possible**: attaching a
  single listener to a stable parent element, then inspecting _which_
  descendant was actually clicked when the event arrives — rather than
  attaching a separate listener to every individual clickable child,
  including ones that don't exist yet.
- The practical skill this unit builds: **treating "what element did this
  event actually fire on" as a question with a precise, checkable
  answer** — not an assumption about what a person visually perceives as
  a single clickable unit.

## Two things that look like the same click, and aren't

|                                              | Click on the button's edge            | Click on the icon                          |
| -------------------------------------------- | ------------------------------------- | ------------------------------------------ |
| Visually                                     | Same button, same person, same intent | Same button, same person, same intent      |
| `event.target`                               | The button element itself             | The icon element, nested inside the button |
| Does `event.target` have class `delete-btn`? | Yes                                   | No — only its parent does                  |
| Naive check result                           | Works                                 | Silently does nothing                      |
