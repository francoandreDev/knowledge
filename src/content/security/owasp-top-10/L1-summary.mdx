A company did the things security fundamentals usually mean: bcrypt
for password storage, TLS on every connection, short-lived signed
tokens for sessions. A pentest still finds a full customer-data
breach in an afternoon — not by cracking the hashing or forging a
token, but by calling `/api/invoices/:id` with someone else's invoice
number. The endpoint checks that a request has _a_ valid session; it
never checks whether _that_ session's user actually owns _that_
invoice. **If the cryptography and the transport were never the weak
point, what was?**

</Scenario>

In plain language: the attacker did not break the password hashing, the
HTTPS lock, or the session token. They found an old door that was still
open and asked it for someone else's data. That is the mental shift in
this unit: security failures are often boring missing checks, not movie
scenes about cracking the hardest lock.

## The shape of the problem

- Attackers overwhelmingly don't break strong cryptography or defeat
  well-implemented TLS — those are hard, expensive, and rarely
  necessary when a much cheaper path exists: a missing check, a
  stale endpoint, an unpatched library, a config left at its
  insecure default.
- The **OWASP Top 10** is a checklist, not a single vulnerability —
  it's the industry's running list of the categories of mistake that
  actually get exploited most often in real breaches, re-ranked
  periodically from real incident data.
- Getting authentication, hashing, and TLS right (covered in other
  units in this track) is necessary but not sufficient — this unit
  is about everything else that has to also be right, and the ways
  it commonly isn't.

## Key terms

- **Attack surface** — every point where an attacker can send input
  to, or receive output from, a system: every endpoint, every form
  field, every header, every third-party dependency.
- **Injection** — untrusted input is interpreted as code or commands
  by a downstream interpreter (a database, a shell, a template
  engine) instead of being treated as inert data.
- **Broken access control** — a system correctly confirms _who_ a
  user is (authentication) but fails to correctly enforce _what that
  specific user is allowed to do or see_ (authorization).
- **Security misconfiguration** — a system is insecure not because
  of a code bug, but because of how it's set up: a debug endpoint
  left enabled, a default credential never changed, a permissive
  CORS policy copy-pasted from a tutorial.
- **Endpoint** — one specific URL or route the app responds to, like
  `/api/invoices/:id`.
- **Staging / production** — staging is a rehearsal environment;
  production is the real version users depend on.

## The ten categories, briefly

1. Broken access control — a user can see or change something that
   belongs to someone else.
2. Cryptographic failures — sensitive data is readable because it was
   not protected, or was protected with the wrong primitive.
3. Injection — text from a user becomes a command by accident.
4. Insecure design — the product rules themselves allow harm even if
   each line of code does what it was told.
5. Security misconfiguration — a risky setting, old route, default
   password, or debug mode is left on.
6. Vulnerable and outdated components — a library has a known public
   flaw and the app still ships it.
7. Identification and authentication failures — login, session, or
   account recovery can be bypassed or abused.
8. Software and data integrity failures — code or data is trusted
   without checking where it came from.
9. Security logging and monitoring failures — the breach happens, but
   the team has no signal that it happened.
10. Server-side request forgery (SSRF) — the server is tricked into
    making a request to a place the attacker cannot reach directly.

## What this unit covers

L2 maps all ten categories at a glance, shows which ones this track
already covers in dedicated units (authentication, hashing,
encryption, TLS), and walks through why an attacker's real process
looks nothing like "find the hardest lock and pick it." L3 goes deep
on three categories this track hasn't covered yet — injection, broken
