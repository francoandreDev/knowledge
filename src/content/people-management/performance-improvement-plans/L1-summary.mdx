A manager has been quietly worried about a report's performance for two
full quarters — missed deadlines, work that needs heavy rework, a
pattern that isn't improving. The manager mentioned it once, gently, in
a 1:1, and otherwise kept hoping it would resolve on its own. Now the
manager is ready to act — but when they raise it directly, the report
is genuinely shocked: **"Nobody ever told me this was serious enough to
put my job at risk."** The manager wasn't lying to themselves about the
performance. So why does the report have a point?

## The shape of the problem

- Underperformance rarely announces itself as a single crisis — it's
  usually a pattern that accumulates quietly, which makes it tempting
  for a manager to keep waiting for "one more data point" before
  acting, long past the point where acting was actually overdue.
- A vague mention in a 1:1 ("let's try to hit deadlines more
  consistently") doesn't function as a warning from the report's side
  — it reads as normal coaching, not as "your job is at risk." The gap
  between what the manager meant and what the report heard is the
  entire problem in the Scenario.
- A **performance improvement plan (PIP)** exists to close exactly
  that gap: it converts a vague, accumulated worry into specific,
  written, time-bound expectations — so "did they improve" has a clear
  yes/no answer instead of a manager's ongoing gut feeling.
- The **"no surprises" principle** is the test a PIP has to pass: by
  the time a formal PIP starts, the report should already know
  performance is a serious problem — the PIP formalizes and
  time-bounds something already communicated, it doesn't introduce it
  for the first time.

## Key terms

- **Performance improvement plan (PIP)** — a formal, written, time-bound
  document specifying exactly what performance must look like, by
  when, to be considered acceptable — used when informal coaching
  hasn't resolved a real performance gap.
- **No-surprises principle** — the standard that nothing in a PIP
  should be the report's first time hearing that their performance is
  a serious problem; a PIP formalizes existing feedback, it doesn't
  introduce new feedback.
- **Documentation trail** — the ongoing, dated record of specific
  performance conversations and examples, kept _before_ a PIP starts,
  that makes the eventual PIP defensible instead of appearing sudden
  or retaliatory.
- **Specific, observable expectation** — a PIP goal stated so
  concretely that whether it was met is a factual question, not a
  matter of opinion (e.g., "ship three code reviews per week with no
  more than one round of revision" rather than "be more thorough").

## What this unit covers

L2 works through the actual sequence a fair PIP process follows — from
the first informal signal, through documentation, through the formal
PIP itself, to its defined checkpoints — and why skipping straight to
a PIP without that earlier documentation is what makes a PIP feel
sudden even when the underlying performance problem was real. L3 walks
the Scenario's exact manager and report through a real PIP: the
document itself, the actual conversation that opens it, and both
possible outcomes at the final checkpoint.
