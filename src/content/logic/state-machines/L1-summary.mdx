A file upload widget tracks its state with four independent boolean
flags: `isUploading`, `isPaused`, `isSuccess`, `isError`. A user
uploads a file, it succeeds — and the UI shows a progress spinner
**and** a green checkmark at the same time. Digging in, the `SUCCESS`
event handler sets `isSuccess = true` but never resets `isUploading`
back to `false`. Nothing in the code stopped that from happening —
the four flags can be set in any combination at all, and only some of
those combinations were ever supposed to be reachable. **If only 5
combinations out of 16 possible ones are actually meaningful, what
was actually stopping the other 11 from happening — before this bug
proved the answer was "nothing"?**

</Scenario>

## The shape of the problem

- Four independent booleans have `2⁴ = 16` possible combinations —
  but a file upload only ever has a handful of _meaningful_ states
  (idle, uploading, paused, succeeded, failed, cancelled). Nothing
  connects "the code allows this combination" to "this combination
  makes sense."
- Every event handler that touches one of these flags has to
  correctly manage all the _others_ too, by convention, by memory,
  forever — and the `SUCCESS` handler above shows how easily that
  convention breaks down.
- A **state machine** collapses "many independent booleans" into a
  single named state, with an explicit, closed list of which
  transitions are even legal — an invalid combination isn't a bug to
  catch later, it's a state the system is structurally unable to
  represent at all.

## Key terms

- **State machine** — a model where a system is always in exactly one
  of a fixed set of named states, and can only move between states via
  explicitly defined transitions.
- **State** — one specific, named condition the system can be in
  (e.g. `uploading`, `paused`, `success`) — not a combination of
  independent flags, a single value.
- **Transition** — a defined rule: "from state X, event Y leads to
  state Z." If no rule exists for a given state/event pair, that
  transition is illegal.
- **Truth table** — a table listing every possible combination of
  boolean inputs and the result for each — used here to show how many
  combinations a set of independent flags actually allows, versus how
  many are meaningful.
- **Invalid / illegal state** — a combination of values that the code
  technically permits but that shouldn't be reachable, like
  `isUploading: true` combined with `isSuccess: true`.

## What this unit covers

L2 works through a truth table for the four-boolean version (showing
exactly how many of the 16 combinations are actually meaningful) and a
state diagram for the fixed-state version of the same upload widget.
L3 implements both versions in real code — reproducing the exact bug
from a naive boolean-flag implementation, then implementing a state
machine with an explicit transition table that makes the same bug
structurally impossible to write.
